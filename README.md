# 多方言 AI 农技与农田数字孪生平台

面向基层农户的农技服务平台：**拍照或说方言描述作物症状 → 多模态融合诊断 → 给出防治方案与用药提醒**，
并提供各省当季病虫害地图、知识图书库与 2026 年惠农政策查询。

本项目是《乡村农技多方言智能服务平台 Python 开发任务清单》的完整实现，六大阶段 33 项任务逐条落地。

---

## 一、快速开始

```powershell
# 1. 激活环境（本项目使用 conda 环境 az）
conda activate az
cd /d "D:\code file\insert"

# 2. 安装依赖（首次）
python -m pip install -r requirements.txt

# 3. 一键启动（会先体检数据与模型，再拉起服务并打开浏览器）
.\start.ps1

# 也可以不经过 start.ps1 直接启动
python scripts\20_run_backend.py
```

启动后：

| 入口 | 地址 |
|---|---|
| 前端首页（中国地图） | http://127.0.0.1:8000/ |
| 接口文档（Swagger） | http://127.0.0.1:8000/docs |
| 服务与各能力状态 | http://127.0.0.1:8000/api/health |

> `.env` 不存在时 `start.ps1` 会自动从 `.env.example` 复制一份模板。
> **不填任何 API Key 也能完整跑通全部功能**（语音与大模型走 Mock 降级），详见第五节。

**依赖方向（硬约束）**：`scripts/` → `src/` ← `backend/`。
`src/` 不 import `backend/`，训练评估与线上推理共用同一份实现（`src/infer/predictor.py`），杜绝逻辑分叉。

**阶段 7 引入的一个例外要说清楚**：本项目此前所有产物都是**只读文件**（谁读都一样）。
`data/farm/farm.db` 是第一个**按用户划分、会被改写**的数据，所以它单独一个目录、
单独一个 SQLite 文件，且**不进版本库**（见 `.gitignore`）。它与只读产物之间的边界是刻意划的：
清掉 `data/farm/` 只丢账号与记录，不影响任何既有功能。

`care` 农作物养护知识（47），留空返回全部 399 条。
⚠ **`pest` 这个分类键装的其实全是病害** —— 键名是加虫害卡片之前留下的，为了不打断首页地图
`?open=lib_pest_*` 的深链与既有过滤才没改；虫害在 `insect` 里。详情接口对虫害卡片会多返回
`pest_type`（取食方式类群）与 `latin`（学名），对病害卡片则返回 `pathogen_type`（病原类型）——
两套字段互不填：虫害卡片没有 `pathogen_type`，病害卡片没有 `pest_type` / `latin`。
前端据 `category` 分两支渲染，也**不要**把两者拼在一起（把「潜叶类」加个「性」字就成了「潜叶类性」）。

服务启动时会预热知识库（`lifespan` 里调一次 `deps.load_library()`），
所以打开图书库页那一下不必再等 1.3 MB 的 JSON 解析。

## 五、API Key 配置与降级行为

复制 `.env.example` 为 `.env` 后填写。**三类能力都支持 `auto|真实|mock` 三态，`auto` 为默认**：
有 Key 就走真实调用，没有就自动降级，接口契约完全不变。

```ini
# 语音：优先讯飞方言大模型，退而用百度，都没有则 Mock
VOICE_PROVIDER=auto
IFLYTEK_APPID=          # 科大讯飞开放平台应用（三项须来自同一个应用）
IFLYTEK_API_KEY=
IFLYTEK_API_SECRET=
BAIDU_API_KEY=          # 百度智能云语音技术应用的 API Key（备用）
BAIDU_SECRET_KEY=

LLM_PROVIDER=auto
DEEPSEEK_API_KEY=       # DeepSeek 平台的 API Key
```

**降级时会发生什么（都如实上报，不伪造结果）：**

| 能力 | 无 Key 时的行为 | 前端表现 |
|---|---|---|
| 语音识别 | 不伪造转写文本，返回空文本 + 明确的未配置说明 | 结果区提示"已跳过语音转写" |
| 方言播报 | 不生成假音频，返回 `mock: true` | 自动改用浏览器内置朗读（仅普通话），并提示不是真方言 |
| 大模型 | 由 `src/content/library_build.py` 的规则模板拼装报告，内容可复核 | 结果区标注「大模型：未配置」 |
| RAG 检索 | 返回空引用列表 | 不显示「知识库引用」区块 |
| 虫害检测 | 返回 `pest: null`，报告里不出现「疑似虫害」区块 | 诊断照常，只是少一路证据 |

**降级不是"假数据"**：Mock 报告的所有内容都来自 `label_map.json` 的病害事实字段与按病原类型整理的
防治要点模板，与知识图书库是同一份文案，可逐条追溯。响应里的 `degraded: {llm, rag, voice, pest}`
字段会如实标注哪些能力走了降级 —— **虫害检测失败同样不编**：宁可少一路证据，
也不会凭空写出没检出的虫害（大模型返回的虫害名还会被拿检测结果反查过滤一遍，见 `src/llm/deepseek_provider.py`）。

> 关于「八大方言」的如实说明，**两家语音服务的能力不同，`/api/dialect/list` 会按当前
> 实际生效的 provider 返回对应结论**（见 `/api/health` 的 `voice.provider`）：
>
> - **讯飞（推荐，`IFLYTEK_*`）**：语音识别用「方言识别大模型」，一个 `accent=mulacc`
>   覆盖 202 种方言，**八种方言免切换全部可识别**。语音合成侧靠发音人 `vcn` 区分方言，
>   八种方言**各自都有方言发音人**（普通话 / 粤语 / 四川话 / 河南话 / 东北话 /
>   湖南话 / 陕西话 / 台湾话），`xfyun_tts_supported` 全部为 `true`。
> - **百度（备用，`BAIDU_*`）**：短语音识别 REST 接口**只提供 3 个方言模型**
>   （普通话 1537 / 粤语 1637 / 四川话 1837），其余 5 种回退普通话，
>   在 `asr_supported` 与 `fallback_note` 中明确标注。
>
> 两边都遵循同一条原则：**不假装支持**。八种方言的取舍标准就是「讯飞 `/v2/tts` 确实
> 有发音人，且本项目用真实 Key 实测出声」——上海话 / 闽南语 / 北京话在讯飞的发音人列表里
> 根本没有；天津话唯一的音色 `x4_zijin_oral` 属「超拟人」接口，实测返回 `11200`。
> 这四种都直接从 `configs/dialect.yaml` 里删掉了，而不是留着靠「回退普通话音色」凑数。

## 七、模型训练与评估结果

**训练配置**：ResNet50 / 224×224 / batch 32 / AMP / AdamW（骨干 1e-4、分类头 1e-3）/
余弦退火 + 3 epoch warmup / label smoothing 0.1 / **WeightedRandomSampler** / 早停 patience 7。

**实测结果**（RTX 5060 Laptop 8GB，测试集 761 条）：

| 指标 | 数值 |
|---|---|
| 训练轮次 | 22 epoch 触发早停（最佳 epoch 15），约 10.7 分钟 |
| 峰值显存 | 1.74 GB / 7.96 GB |
| Top-1 准确率 | **0.8975** |
| Top-3 准确率 | 0.9606 |
| Top-5 准确率 | 0.9777 |
| macro P / R / F1 | 0.6686 / 0.7411 / **0.6917** |
| weighted P / R / F1 | 0.8563 / 0.8975 / 0.8719 |

**务必以 macro 指标为准**：本数据集严重不均衡（10 个大类占 7555/10165 张，261 个小类各仅 10 张），
weighted 指标会被长尾大类拉高约 20 个百分点。macro-F1 0.69 才反映真实水平。
这也是训练时启用 `WeightedRandomSampler` 的原因 —— 不加权的话模型只要全预测成那 10 个大类
就能拿到 74% 的准确率，而 261 个小类会几乎全错。

**已知局限**：多数类别在测试集中只有 1 张样本（8:1:1 划分下 10 张的类只能分到 1 张），
因此单类的 precision/recall 波动很大（非 0 即 1），分类级别的指标仅供参考，
应按作物大类或 Top-3 命中率来解读模型能力。
完整报告见 `outputs/reports/eval_resnet50.json`，混淆矩阵见 `outputs/figures/confusion_matrix_resnet50.png`。

### 虫害目标检测（IP102 / YOLOv8n，阶段 2.7）

**训练配置**（照 PestYOLO 的 `train.py` 复现）：yolov8n / 640×640 / batch 16 / 30 epoch / AMP。
与上面那条链路是**两套完全独立的标签空间**：这里是 102 类 IP102 目标检测（输出框），
上面是 271 类 PDD271 单标签分类（输出概率）。两者互不覆盖、互不换算。

**实测结果**（RTX 5060 Laptop 8GB）：

| 指标 | 数值 |
|---|---|
| 训练轮次 | 30 epoch 跑满（无早停），约 49.5 分钟 |
| 峰值显存 | 2.53 GB / 7.96 GB |
| 逐轮 mAP50 最佳 | 0.5062（第 30 轮，**仍在上升，未见平台**） |
| val 评估 | mAP50 **0.5025** / mAP50-95 0.3214 / P 0.4785 / R 0.5459 |
| test 评估 | mAP50 0.4982 / mAP50-95 0.3118 / P 0.5166 / R 0.5015 |
| val 覆盖类别 | 97 / 102（test 96 / 102） |
| 导出 ONNX | 12.98 MB，opset 17，静态 640×640，单文件 |

**为什么「逐轮最佳 0.5062」而评估只有 0.5025** —— 这不是训练结果对不上，是**两个不同的检查点**。
ultralytics 挑 `best.pt` 用的是 fitness，而本版本它的权重是 `[P, R, mAP50, mAP50-95] = [0, 0, 0, 1]`，
**只认 mAP50-95**。训练日志里能直接看出来：mAP50-95 的最高点在第 29 轮（0.3209），
mAP50 的最高点在第 30 轮（0.5062）。所以 `best.pt` 是第 29 轮，它在 val 上独立评估得 0.5025。

**30 轮没跑到平台期**：mAP50 从第 1 轮 0.0542 一路爬到第 30 轮 0.5062 仍在涨（第 10 轮 0.4028、
第 20 轮 0.4799）。继续训（比如 100 轮）指标还会提高，本次按复现口径停在 30 轮。

**最弱的五类**（val，只列有实例的）：苜蓿斑蚜 0.000（1 个实例）、康氏粉蚧 0.000（4）、
吹绵蚧 0.000（24）、芒果切叶象甲 0.000（5）、麦二叉蚜 0.009（4）。
弱点集中在**蚜虫与蚧类**：虫体小、在整叶照片里只有几十个像素，再叠加长尾类样本少。

**官方权重对照做不了，如实留空**：原计划要把 PestYOLO 仓库自带的 `best.pt` 用同一份 val
跑一遍做并列对照（既是复现是否到位的证据，也顺带验证类序互通），但**四个源全部拉不到**：
直连 `raw.githubusercontent.com` 在本机 DNS 解析失败，三个代理（含 main / master 两个分支）
一律 404。失败原因的原样记录写在 `outputs/reports/eval_pest_yolo.json` 的 `baseline_note` 字段里，
不是一句空洞的 `null`。想补上这个对照，可人工把权重放到 `models/pretrained/pestyolo_ip102_best.pt`
再重跑 18 号脚本（第一步就会命中本地缓存）。

完整报告：`outputs/reports/eval_pest_yolo.json`（val）、`eval_pest_yolo_test.json`（test）；
混淆矩阵与 PR 曲线：`outputs/figures/pest_confusion_matrix.png`、`pest_pr_curve.png`。

**ONNX 导出做了四道对齐校验**（脚本 19，全过，理由见该文件 docstring）：

| 校验 | 结果 |
|---|---|
| A 预处理：自写 letterbox vs ultralytics，逐像素 | 20 张图 × auto∈{False,True} 全等 |
| B 导出保真：同一张量 torch 前向 vs ONNX 前向 | 最大绝对误差 2.17e-03 |
| C 后处理：自写 numpy vs `non_max_suppression` | 类别 id 全等、IoU 1.0000（**只有 1 张图 1 个框，判据偏薄**） |
| D 端到端：自写全链路 vs `YOLO.predict()` | 20 张图 20 个框、最差 IoU 0.9982（4 张无检出） |

C 的样本量确实薄，所以真正的兜底是 D —— 它覆盖 20 张图、跨 4 个尺度，且允许「无检出」的情形参与统计。

低 1 天、分位覆盖率落在 0.70–0.90、验证集 ≥500 行 / ≥50 组。过了且加 `--install`

> 一次要 22 年 × 3 个变量，这种重请求一个小时只能发出去几十次；撞上限时服务端给的是
> `HTTP 429（Hourly API request limit exceeded）`——**「小时」窗口**，在同一个窗口里

> 睡过头、被关掉、断电都无所谓，重跑就是接着拉。
>
> **绝不为省时间而合成天气**：拉不到就让它缺，缺的那一季在第 31 步被丢弃并**计数**。
>
> 首次实跑（只有 21 个县时）闸门**未通过**，卡在覆盖率 0.414（要求 0.70–0.90），
> 而 MAE 21.08 天已经低于基线 26.25 天 —— 缺口来自「只有一个省在训练」的域偏移，
> 样本拉全后才会是有效评估。完整数字与两条结论见 `docs/datasets.md`。

## 九、环境与依赖

- **Python**：3.11（conda 环境 `az`）
- **PyTorch**：2.14.0+cu130（由 conda 提供，`requirements.txt` 不锁定以免覆盖 CUDA 版本）
- **GPU**：RTX 5060 Laptop 8GB（预期可用；CPU 也能跑，只是训练慢）
- **关键依赖**：torchvision / timm / albumentations / fastapi / uvicorn / onnx / onnxruntime /
  onnxscript / pandas / scikit-learn / requests
- **仅训练虫害检测时才需要**：`ultralytics`（+ 导出用的 `onnxslim`）。**服务进程不依赖它** ——
  检测同样是导出 ONNX 后用 `onnxruntime` 跑（见下），所以没装也能正常启动与诊断

几个刻意的技术选择：

- **ONNX 推理只用 CPU 版 `onnxruntime`**：本机 torch 是 cu130，`onnxruntime-gpu` 通常滞后于 CUDA 13，
  强行上 GPU 版容易踩版本地狱。单图 CPU 推理实测分类约 20~30 ms，完全够用。
- **`ultralytics` 不进服务进程**：它是 AGPL-3.0，且运行时依赖 torch；本项目只在
  `scripts/17~19` 三个脚本里用它（训练 / 评估 / **导出**），线上只吃导出的 ONNX。
  装它之前的环境快照在 `outputs/reports/pip_freeze_before_pest.txt`，必要时可精确回滚。
  唯一已知的污染面是它会装一个 `opencv-python`（与既有的 `opencv-python-headless` 并存，
  两者都提供 `cv2`），装完请立刻跑一遍 `22_verify_artifacts.py` 确认既有 ONNX 链路仍是绿的。
  另：`ultralytics` 默认会同步匿名使用数据，本项目已设 `settings.update({"sync": False})` 关掉。
- **前端零外网依赖**：ECharts 与中国地图 GeoJSON 都打包在 `frontend/assets/` 下，
  农村弱网或离线环境同样可用；字体用系统字体栈（`Noto Sans SC` → `Microsoft YaHei` → …）同样不拉外网。
- **录音不用 `MediaRecorder`**：它默认产出 webm/opus，两家的识别接口都不收。
  因此前端改用 Web Audio API 采集原始 PCM，重采样到 16kHz 单声道后自行封装 WAV 再上传。
  百度侧直接吃这个 WAV；讯飞的方言大模型要裸 PCM（`encoding=raw`），由后端按 RIFF chunk
  找到 `data` 偏移剥掉包头，**不硬编码 44 字节**——带额外 chunk 的 WAV 也能正确取出数据。

## 十、常见问题

**Q：`08_build_rag_index.py` 卡在下载向量模型？**
国内直连 `huggingface.co` 会超时。本项目默认已把 `HF_ENDPOINT` 指向 `https://hf-mirror.com`，
并设了 `HF_HUB_DISABLE_XET=1` 禁用 Xet 存储后端（其域名 `cas-bridge.xethub.hf.co` 在国内不通，
开着会一直卡在 "Trying to resume download..."）。若仍失败，可：
① 在 `.env` 里换一个可用的镜像；② 手动下载模型放进 `models/pretrained/hf/`；
③ 直接 `RAG_ENABLED=off` 跳过 —— 诊断功能不受影响，只是不显示知识库引用。

**Q：页头/结果区提示「大模型未配置」「语音服务未配置」？**
说明该能力的 Key 没配。访问 `/api/health` 可以看到每个能力的当前状态与原因。

**Q：注册完怎么就有三块田了？**
那是**示例田**（名字里带「示例」），注册时自动建的，目的是让新账号一进「我的农田」
就能看到完整的 3D 长势、天气与积温 —— 空页面演示不出任何东西。
三条田刻意覆盖三个作物 × 三个生长阶段（分蘖期水稻 / 抽穗期玉米 / 成熟期油菜），
顺便把三套完熟形态都展示出来。它们是**演示数据**，可以随手改名或删掉。

**Q：示例田为什么带经纬度？**
天气、积温、3D 参数全部依赖坐标 —— 位置留空的话示例田就只是一行没有内容的记录。
所以注册时填了武汉（114.30, 30.58），并写进 `user_settings` 作为新建田块的默认值。
换地方直接改田块信息即可（`PATCH /api/farm/fields/{id}`）。

**Q：农田页说「预报不可用，以下为当地多年气候平均值（不是预报）」？**
这是 7.2 的降级第三条在起作用：Open-Meteo 取不到预报时，用该省该市多年的同日平均气温
顶上，并**明确标注它不是预报**。同时「今天该干啥」会跳过所有天气类提醒
（不会拿气候平均值去说「未来 3 天有雨」），并告诉你跳过了。
历史气温取不到时还有另外两档降级：读缓存并标「截至 X 日」；连缓存都没有就
`confidence=低`、只显示已累积积温。**任何一档都不会编一个看起来正常的数字。**

**Q：收获预测为什么是「积温法」而不是 XGBoost？**
因为模型还没训练 —— 触发条件是**全平台 `harvest_records` 累计 ≥ 30 条**
（清单 7.3.4 定的）。一个刚部署的平台上不可能已经有 30 茬收获记录，
所以演示时 `method=gdd_fallback` 是设计状态而非未完成。
点「我收了」可以积累样本；够了之后跑 `python scripts/24_train_harvest_model.py`，
服务无需重启即可切到 XGBoost（训练完会清模型缓存）。

**Q：那我能不能不等那 30 条，直接用网上的数据集把模型训出来？**
能，而且这正是**更该走的那条路** —— 见 `docs/datasets.md` 与上面「用公开数据集
把收获模型训出来」那一段（`scripts/29 → 30 → 31 → 32`）。

要提醒一点：本地那条 24 号脚本**造不出可用的标签**。库里存的是「收获当天」那一刻的
特征快照，而标签是全生育期总天数，于是 `days_since_sow ≈ 那天的天数`，
模型只会学成一个恒等映射；可线上把模型输出当作**「从观察日到成熟的剩余天数」**用
（与积温区间同列取 min/max），结果是收获日被系统性推晚。
`predict_harvest` 一行没改 —— 改的是训练侧：外部数据集能给出「一个生长季里多个
观察截止日」，那才有「进度越靠后 → 剩余天数越小」这张映射可学。
所以 `24` 见到外部产物会**拒绝覆盖**（除非 `--force`）；
要彻底修好本地那条路，得在生长季里周期性快照特征（新表 / 新记录），当前没做。

**Q：访问别的用户的田块返回 404，是不是接口有 bug？**
不是，是故意的（7.0.5）。跨用户访问统一返 **404 而不是 403** ——
403 等于告诉对方「这条记录确实存在，只是不属于你」，那本身就是一次信息泄露。
删除同理：`DELETE` 别人的田块返 404，且**对方的数据一行都不会动**（有专测锁住）。

**Q：打开农田页时控制台有一行 three.js 的弃用提示？**
来自 Three.js 自己：r150+ 起 UMD 构建（`build/three.min.js`）被标记为弃用，
建议改用 ES Module。本项目仍然用它，是因为要跟既有的 ECharts 保持同一套约定 ——
本地打包、普通 `<script src>` 引入、零外网依赖、无构建步骤。r160 是最后一个带 UMD 的版本。
改走 ESM 的话，`farm3d.js` 要变成 `<script type="module">`，也就不能再靠全局变量
与其他页面脚本通信了 —— 为一个提示付这个代价不值。

**Q：填了讯飞 Key，语音还是走 Mock？**
看后端启动日志：`VOICE_PROVIDER=iflytek` 但任一凭证缺失时会打一行 error 再降级，
`/api/health` 的 `degraded.voice` 也会变 `true`。三项凭证（`IFLYTEK_APPID` /
`IFLYTEK_API_KEY` / `IFLYTEK_API_SECRET`）必须来自**同一个应用**，否则识别会报 `10313`。

**Q：识别报 `11200` / 播报没有方言味？**
`11200` 是「功能未授权」——方言识别大模型与 TTS 发音人都要在讯飞控制台**单独开通/添加**
之后才有权限，`configs/dialect.yaml` 里的 `xfyun_vcn` 只是默认值。按控制台实际开通的
发音人改配置即可，**不需要改代码**。八种方言都配了各自的发音人，若某个 `vcn` 在自己
账号下未开通，可在控制台添加对应发音人，或把该方言从配置里删掉——两条路都不用改代码。

> 顺便记一个实测结论：`11200` 不一定都是「没开通」。天津话的 `x4_zijin_oral` 在本机
> 账号上报的也是 `11200`，但根因是它属讯飞的**「超拟人」接口**（另一个 `wss` 端点 +
> 另一套请求体），本项目调的 `/v2/tts` 上根本不存在这个音色——开通也解决不了，
> 只能换接口或不用。这也是天津话没进八大方言名单的原因。

**Q：识别报 `10106 wrapper output data invalid(key or type)`？**
这是**真实踩过的一个坑**，现已修复：请求里少了一个输出封装节点。讯飞的语音听写大模型
文档把 `parameter.iat.result`（`{"encoding":"utf8","compress":"raw","format":"json"}`）
标为**非必传**（默认值就是这三项），但方言大模型的 wrapper **不接受缺省** ——
少了它整条请求被拒，返回的正是这个 10106。
最容易误导的是报错里的 `key or type`：它读起来像凭证或音频格式出错，于是很容易去换音频、
查 Key，甚至误判成「方言模型没在控制台开通」。实测同一段 16 kHz 中文语音、
其余字节完全一样，只补上该节点即 `code=0` 正常出字；把 `accent` 从 `mulacc` 换成
`mandarin` 也照样 10106 —— 与方言授权无关。
它属于 `parameter.iat`（响应字段配置），跟 `payload.audio.encoding`（音频编码）是两回事：
放进 `payload` 会被服务端判为 `unknown field` 并直接关闭连接。
`tests/test_units.py` 现在有一条用例把这两处都锁住了（必须在 `parameter.iat` 里、且不得进 `payload`）。

**Q：图书库点了麦克风，却提示「浏览器不支持录音」？**
先看访问地址。浏览器的录音 API 只在**安全上下文**里存在：`http://127.0.0.1:8000` 与
`localhost` 算，`http://<局域网 IP>:8000` **不算** —— 这种访问方式下
`navigator.mediaDevices` 直接是 undefined，表象与「浏览器太旧」一模一样。
用手机从局域网访问开发机时最容易踩到，改用 127.0.0.1，或给站点配上 https。
页面把这两种情况分开提示（「不支持录音」vs「录音需要 https 或 127.0.0.1」），
所以看到哪一句基本就能定位。真换了现代浏览器仍录不到，再依次查：麦克风权限被拒
（提示里会带上原始原因）、设备被其它程序独占、以及后端语音接口是否配好了 Key。

**Q：诊断页点「调用摄像头拍摄」，出来的还是选照片？**
先看访问地址 —— 与录音是同一条规矩：媒体采集 API 只在安全上下文里存在，所以
`http://<局域网IP>:8000` 下开不了摄像头，页面会安静地回落成文件选择器（这是有意的，
不留死胡同）。桌面用 `127.0.0.1` 就够；手机要真开摄像头，跑
`python scripts\33_make_dev_cert.py` 生成自签证书，再
`python scripts\20_run_backend.py --https --port 8443`，手机访问
`https://<局域网IP>:8443/diagnose.html`，首次会提示证书不受信任 —— 选「高级 → 继续前往」。
地址没问题却仍打不开，看提示语：说「没有拿到摄像头权限」就是浏览器权限被拒（点地址栏
左侧的锁 / 摄像头图标改成「允许」），说「没有找到可用的摄像头」就是设备层面没有可用摄像头
（被其它程序独占也算）。取景代码单独放在 `frontend/assets/js/camera.js`，与诊断页的
业务逻辑互不牵扯；它拍出来的是一张普通的 JPEG `File`，与选文件上传走的是**同一条**提交链路。

**Q：改了省份病虫害数据，首页还是旧的？**
首页优先用本地快照 `frontend/assets/data/home_preload.js`（生成物，挂在
`04_gen_province_pest.py` 末尾自动同步）。手工改完数据后重跑一次
`python scripts\15_bundle_frontend_data.py` 即可；前端还有一道后台校验，
发现快照与接口不一致会自动换成接口数据并提示「首页数据已更新」。

**Q：图书库页显示了「当前展示的是本地快照」？**
这是**后端没启动**时的兜底：`frontend/assets/data/library_preload.js` 是同步加载的，
所以列表照常能翻，只是检索、翻页与卡片正文都走不了 —— 后面两项本来就要请求接口。
启动 `python scripts\20_run_backend.py` 后刷新即恢复。
（页面上方那条「无法获取服务状态」是另一个元素，归 `layout.js` 管，两者互不影响。）

**Q：页面上出现一个**没有内容的空白框**？**
那是一个「带着 `hidden` 却仍然可见」的元素。`hidden` 属性靠浏览器默认样式表里的
`[hidden] { display: none }` 生效，而**作者样式里任何一条 `display` 都会把它盖掉** ——
本项目最典型的是 `.notice { display: flex }`：于是图书库顶部那两条提示条（快照提示条与
服务状态条）明明带着 `hidden`，却渲染成有边框、有底色、没有内容的空框。
现在 `base.css` 里有一条全局的 `[hidden] { display: none !important }` 兜底，
这一整类问题都不会再出现。**代价是**：凡是「填了内容想让它出现」的地方都必须显式写
`hidden = false`，光写 `innerHTML` 是不够的 —— `layout.js` 里降级条的失败分支就曾经漏了这句
（它以前能显示，靠的正是同一个 bug 的反面）。加新的提示条时照这两条来即可。

**Q：重建了知识库，页面还是旧的卡片？**
同一套道理：`07_build_library.py` 末尾会自动重打 `library_preload.js`，
但如果你是用别的方式改的 `library_items.json`（或手工编辑过），
重跑一次 `python scripts\15_bundle_frontend_data.py` 就同步了。
`22_verify_artifacts.py` 会核对快照与 `library_items.json` 是否一致，不一致会直接报出来。

**Q：`/api/health` 说虫害检测模型没就位，但诊断页明明能出检测框？**
这是**真实出现过的一个 bug**：`main.py` 组装 `pest_detector` 那一段把 detector 的阈值属性
写成了 `confidence_threshold`，而 `OnnxPestDetector` 上挂的是 `conf_threshold`，
于是那一整块抛 `AttributeError` 落进 except，health 对着一个装好、也跑得动的检测模型
报 `available: false` —— 同一时刻 `/api/diagnose/multimodal` 正拿它出框，两处自相矛盾。
现在这个坑有两条测试锁着：冒烟测试会核对「health 说的可用与否」与「ONNX 文件在不在盘上」
是否一致，单元测试则拿 detector 的返回键去比后端 schema 的字段声明。
若你改过 detector 的属性名，先看 `pest_detector` 里的 `error` 字段，它会把原始异常原样带出来。

**Q：换台机器后模型加载失败？**
`models/registry.json` 里记录的是绝对路径。重新跑一次 `python scripts\13_export_onnx.py` 会更新路径；
或直接删掉 `registry.json`，后端会按约定路径 `models/onnx/inference_model.onnx` 查找。

**Q：`onnxruntime` 报找不到 `.onnx.data` 文件？**
导出时把权重写到了外部数据文件。本项目已强制 `external_data=False` 输出自包含单文件；
若你手动改过导出参数，请连同 `.onnx.data` 一起拷贝，或重新导出。

**Q：训练中断了怎么续？**
当前实现保存 `last_resnet50.pth`（含优化器状态）但不自动续训，重新运行会从头开始。
数据与配置都在，重跑一次的代价约 10 分钟。

**Q：地图上省份没有颜色？**
该省的主要作物在本数据集中没有对应病害类别。`data/province_pest_top3.json` 里每个省都带
`crops` 与 `threat_scope` 字段，可以直接核对。

**Q：政策摘要能不能改？**
改 `src/content/policy_fetch.py` 里的解析规则后重跑 `05_fetch_policies.py`；
抓取失败时会写入带 `demo_data: true` 的回退条目，接口照常返回不会中断。
